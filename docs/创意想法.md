# 下班搭子 · 双人互动设计方案

> 更新：2026-10-20。本文为可讨论、可调整的设计方案。规划能力不代表已经实现，完成情况以代码与验收为准。

实现进度（v0.3.0）：已完成两个角色的同人桌面适配、搭子面板、匿名设备身份、一次性邀请、动作与回执、暂停、断线重连、离线解除，以及单实例配对服务端。已通过临时服务与两个真实 Qt 客户端联调；尚未部署公共 HTTPS 服务或验证真实公网网络环境。操作见 [联网与部署](联网与部署.md)，形象参考见 [形象来源](形象来源.md)。

## 1. 产品定位与原则

一只陪你工作的 Windows 桌面宠物。用户可以独自使用，也可以自愿连接一位搭子，通过宠物动作传递陪伴；连接可以随时暂停或解除。

情侣是重点场景，也允许朋友、家人使用。不判断现实关系，不要求填写关系类型。界面默认使用“搭子”，不使用“已有伴侣”等现实关系判断。

- **本地功能完整：** 不连接搭子，也能使用倒计时、拖动、大小和透明度、气泡、摸头、换形象等功能。
- **联网主动开启：** 首次运行不弹配对引导、不显示未配对红点；未启用时不申请设备身份、不连接互动服务。
- **不要求注册：** 不填写手机号、邮箱和密码，不增加登录页；必要的设备身份与请求验证由程序自动完成。
- **结果真实清楚：** 配对、发送、暂停和解除都给出明确反馈，不能把本机动画当作送达确认。
- **接收方控制打扰：** 可以暂停远程互动，不抢焦点、不强制声音、不无限播放连续动作。
- **状态不监控人：** 只说明程序是否可互动，不推断人在不在电脑前，不显示最后活跃、已读或回应率。

以上是设计取舍的依据，不把早期方案写成“不可协商”的产品原则。

## 2. 首期形象与自由选择

### 2.1 已明确的需求

- **首期只有两个形象：噜噜、噜妹。** 按用户后续要求，从网络查找形象参考，来源与同人适配范围已记录。
- **双方各自自由选择自己的宠物，可以选择同一个形象。**
- 不按性别、现实关系或发送方/接收方分配，不要求“一人噜噜、一人噜妹”。
- 未配对也可选择两个形象；配对、解绑不改变本地形象选择。
- 换形象不需要对方同意，不改变配对关系，也不强制改变对方的宠物。
- 两个形象支持同一组功能与动作，后续可扩展更多形象。

这部分是对原需求的明确，不是新增“允许自由选择”的规则。

### 2.2 两边分别怎样表现

每台电脑上的主宠物始终使用本机用户选择的形象。发动作时，本机宠物表现“发起”；收动作时，对方电脑上的宠物以对方选择的形象表现“被互动”。

例如，A、B 都选择噜噜：A 发送捏脸，A 的噜噜做发起动作，B 的噜噜做被捏动作。两边选择不同形象时遵循相同规则，不临时替换角色。

搭子面板可显示对方所选形象的小预览，只同步形象标识，不上传图片。对方离线时允许显示上次同步的形象，不宣称实时更新。

### 2.3 素材与动画

参考图只确定形象，不等于已经具备所有动画。需要先确定透明背景、逻辑尺寸、缩放效果、角色定位点，以及逐帧绘制或分部件动画的制作方式。

制作顺序可以先用一个角色验证动作，再适配第二个；**首期交付仍包含两个可自由选择、动作完整的形象。**

两者共同具备：待机呼吸、眨眼、目光跟随、摸头回应、拖动反应、挥爪、发起/接收捏脸、发起/接收轻捶。连接状态通过面板或小标识显示，不要求宠物一直保持某种“离线表情”。

## 3. 桌面交互与功能入口

| 操作 | 行为 |
| --- | --- |
| 按住拖动宠物 | 移动并记住位置，不误触远程动作 |
| 单击宠物 | 本地摸头；按气泡模式决定是否展示倒计时 |
| 双击宠物 | 打开设置，不重复触发单击 |
| 右键宠物或托盘 | 打开菜单 |
| Ctrl + 滚轮 | 调大小 |
| Ctrl + Shift + 滚轮 | 调不透明度 |

保留置顶、鼠标穿透、工作日、下班时间等现有配置。穿透时不能点击、拖动或用滚轮调整，可从托盘恢复。

右键及托盘增加“搭子…”入口，打开轻量面板：

- 未配对：生成邀请、输入邀请码、关闭联网。
- 已配对：对方形象、互动可用状态、动作按钮、暂停互动、解除连接。
- 可添加仅存本机的备注称呼，不建立公开资料。
- 不常驻大窗口，不增加好友列表或聊天界面。

本地摸头与远程动作分开，避免用户只是摸自己的宠物，却向搭子发送了动作。

### 气泡、隐藏和声音

倒计时气泡保留常驻、悬停、点击、悬停或点击、隐藏五种模式。默认“悬停或点击”：平时隐藏，鼠标滑过宠物或点击时才展示，也可选择始终展示。远程互动文案单独设置，关闭倒计时气泡不自动关闭远程动画。

| 本机条件 | 远程互动处理 |
| --- | --- |
| 宠物可见、接收开启 | 可播放动作，文案受独立开关控制 |
| 暂停互动 | 不播放、不提示、不积累待播动作 |
| 隐藏宠物 | 首期视为暂不接收，发送方得到对应反馈；重新显示不补播 |
| 鼠标穿透 | 不妨碍播放已允许接收的远程动画 |

声音默认关闭，远程互动声音与下班提醒声音独立。首期不读取屏幕内容自动判断会议或工作状态，用户可从托盘一键暂停互动。

## 4. 无注册的设备身份

不注册指不要求用户填写账号信息，不表示服务器完全不验证请求。

首次主动开启联网时，程序申请随机设备身份与私密凭证，之后自动使用。不把邀请码当日常请求凭证，不采集硬件指纹绑定用户。

凭证保存在 Windows 当前用户可访问的受保护存储中，不与可分享的普通配置混放。日志不记录完整凭证和邀请码。保留传输保护、权限校验和限频，这些不增加注册页面。

首期一台安装实例对应一个身份，一个身份同一时间只能连接一位搭子，也只允许一个有效互动会话。多设备以后单独设计。

## 5. 邀请与配对

### 5.1 流程

1. A 主动点击“生成邀请”。
2. 程序显示一次性邀请码和有效期，提示分享给想连接的人。生成并主动分享表示 A 愿意连接。
3. B 输入邀请码，点击“连接搭子”。
4. 服务端校验双方身份、邀请和关系，成功后一次性建立双向关系，使邀请失效。
5. B 看到成功；A 在线时收到结果，离线时下次连接后同步。

首期不额外要求 A 再点一次同意。简化的前提是邀请由 A 主动生成、短期有效、可撤销且仅使用一次。持有码者仍可兑换，因此界面需提醒不要公开分享。

### 5.2 建议初值

- 8 位随机大写字母/数字，排除易混淆字符，支持复制粘贴。
- 有效期 10 分钟；一个身份同时保留一个有效邀请，重新生成使旧邀请失效。
- 成功配对、主动撤销或到期后失效，不使用永久个人配对码。
- 生成和兑换由服务端限频，阈值在联调时确定，不默认增加频繁验证码。
- 不能连接自己；任何一方已有关系时都不覆盖原关系。

这些是方案初值，不是用户已经指定的固定参数。

| 情况 | 提示 |
| --- | --- |
| 格式不符合 | 邀请码格式不正确 |
| 不存在、已使用、已撤销或对方当前不可连接 | 邀请码不可用，请联系对方重新生成 |
| 能明确识别已过期邀请 | 邀请码已过期，请重新获取 |
| 自己已配对 | 请先解除当前搭子连接 |
| 输入自己的邀请 | 不能连接自己 |
| 网络异常、结果未确认 | 暂时无法确认连接结果，重连后自动核对 |

不向未配对的人提示“对方已有伴侣”。服务器统一保证一对一和一次性兑换；并发操作或请求重试不能建立重复关系，也不能让双方得到相反结果。

## 6. 状态、暂停与断线恢复

| 对方状态 | 含义 | 能否发送 |
| --- | --- | --- |
| 可互动 | 最近确认连接正常且允许接收 | 可尝试发送，仍需确认结果 |
| 暂不可达 | 离线、休眠或连接超过有效期限 | 不允许 |
| 暂不接收互动 | 在线，但主动暂停或宠物被隐藏 | 不允许 |

自己未连上服务时显示“正在连接”或“连接失败”，对方状态显示未知，不用缓存状态冒充实时状态。

状态只描述程序连接和接收能力，不表示人正在工作、人在电脑前或人已经看到互动。不展示最后活跃、已读、累计次数和回应率，不把“避免猜忌”作为可保证的产品结果。

初始采用长连接和心跳，例如每 10 秒心跳、连续约 30 秒无有效响应判定暂不可达。参数需要实测，不承诺断网瞬间就更新状态。

重连顺序：验证身份 → 核对关系并处理待同步解绑 → 同步暂停及可见状态 → 更新形象 → 开放动作。关系未核对完成前不接收旧连接动作。

暂停状态本机保存，重启后保留。断网优先显示暂不可达，恢复后再显示接收状态。

## 7. 互动动作、反馈与防打扰

### 7.1 首期两组动作

先保留原设想中的**捏脸、轻捶**，轻捶按玩闹、夸张回弹设计。

| 动作 | 发送方自己的宠物 | 接收方自己的宠物 |
| --- | --- | --- |
| 捏脸 | 伸爪做捏的动作 | 脸颊被捏、回弹 |
| 轻捶 | 抬爪轻敲 | 轻微晃动、恢复 |

后续候选为抱抱、送心心、戳一下。是否提前用一个正向动作替换首期动作，在原型试用后确定，不在首期同时扩展所有动作。

### 7.2 发送与接收结果

1. 点击动作后播放本机发起动画，显示“正在发送”。
2. 服务端再次校验关系、连接和接收状态，然后转发。
3. 接收端校验关系版本、唯一动作标识和有效期；可播放时进入短队列并确认。
4. 发送方显示“对方客户端已接收”，不表示对方本人看见。
5. 暂停、解除、过期、明确不可达时，给出对应未送达原因。
6. 回执超时但结果无法确定时显示“未确认送达”，不假称明确失败，不自动重新发送。

动作初始有效期建议 5 秒；入队后实际播放前仍检查有效期和关系。用唯一动作标识去重。回执丢失可能出现“对方已播放、发送方未确认”，需如实呈现。

### 7.3 连点与动画调度

- 同一动作短窗口合并，示例为 1 秒内“被捏 ×3”；只表示这一组互动，不是历史统计。
- 限制发送频率、合并数量及持续播放时间，具体值经两台电脑试用确定。
- 不做无限队列，最多保留一组短暂待播远程动作；新动作合并或明确拒绝。
- 暂停或解除时清空待播远程动作。
- 优先级为：拖动/设置操作 → 本地摸头 → 远程动作 → 待机。远程动作不能打断高优先级操作，过期未播则丢弃。
- 下班计时独立运行，不能因动画漏发下班提醒。

不做离线补发、留言和互动历史。服务端不持久化动作内容，客户端不保存可回看的记录；允许为短暂投递、去重、合并和回执保留有过期时间的内存状态。

## 8. 解除连接、关闭联网与换电脑

### 8.1 解除连接

任意一方可单方面解除，不需要对方批准。入口放在搭子面板，用一次简短的本机确认避免误点，不要求另一方同意。

- 在线且服务端确认成功：关系失效，双方停止发送，待播动作作废，之后可以重新配对。
- 对方离线：服务端仍解除，对方上线后先同步结果再开放互动。
- 自己离线：本机立即停止接收并清空待播，显示“解除待同步”；同步成功前不宣称服务端已解除，也不能新配对。
- 对方看到中性提示“搭子连接已解除”，不弹强打扰通知。
- 清除本机该关系的备注和形象缓存；本地形象、倒计时设置保留。

每次配对产生新关系标识/版本，旧动作、回执和解除结果不能影响新关系。

### 8.2 三种操作的区别

| 操作 | 关系 | 连接与接收 |
| --- | --- | --- |
| 暂停互动 | 保留 | 保持联网，但拒绝远程动作 |
| 关闭联网 | 保留 | 断开连接，对方最终看到暂不可达 |
| 解除连接 | 服务端确认后撤销 | 停止原关系，可重新配对 |

重新开启联网时先核对关系，不补播关闭期间的动作。

### 8.3 换电脑或重装

首期不做多设备和凭证导出。换电脑或重装视为新身份，需要重新配对；另一方可以解除旧关系后重新邀请。

不宣称没有凭证、没有旧设备时能自动找回身份。后续再评估安全迁移和多设备。

## 9. 实现设计与服务边界

以下是建议架构，不代表已开发或部署。

### 9.1 客户端

沿用 Python + PySide6。网络、关系和动作调度独立成模块，不直接堆进宠物绘制代码。

- UI 负责绘制和操作；网络使用异步信号/回调，不阻塞拖动、动画和本地计时。
- 连接管理负责连接、心跳、退避重连、暂停与关闭。
- 关系管理负责配对、核对、解绑与离线待同步。
- 动作管理负责有效期、回执、去重、合并和播放优先级。
- 形象采用稳定标识和动作清单，两套形象共用接口；资源缺失时退回待机，不使程序退出。

### 9.2 服务端

首期使用单个轻量 FastAPI 服务：HTTPS 接口完成设备初始化，安全 WebSocket 长连接处理邀请、关系、状态与动作。邀请与关系采用有请求标识及结果回执的命令，不要求额外的 HTTP 往返。

小范围试用可使用单实例服务与 SQLite，关系变更用事务和唯一约束。连接、动作及回执只短暂保留在内存。多实例、扩容和消息系统另行评估，不提前引入。

最少持久化设备身份与凭证验证信息、当前关系及版本、有效邀请和过期信息，以及离线核对所需的最新关系状态。不保存聊天或动作历史。

服务重启后客户端重连、核对关系，未送达的内存动作不恢复。服务不可用不影响本地功能。

联网试用前需确定部署位置、域名/证书、可用性目标和维护费用；本文不预设购买服务器或开通付费服务。

## 10. 交付顺序

1. **形象与动作原型：** 根据两张参考形象确定资源方案，先验证动作再完成两个形象，比较同款和不同款的互动效果。
2. **本地交互整合：** 完成搭子面板原型，理清气泡、隐藏、暂停、鼠标操作和动画优先级。
3. **最小联网闭环：** 两台电脑完成邀请、双向关系、两组动作、接收确认、暂停、解除和重连。
4. **故障验证与试用：** 覆盖断网、休眠、连点、服务重启和旧关系动作，再调整参数。

首期不同时扩展聊天、更多角色、全部候选动作或多设备。

## 11. 首期验收场景

- 不启用联网，也能完整使用本地功能，没有注册或配对打扰。
- 双方能选同款或不同款，任一方换形象不改变另一方选择，两个形象都具备完整动作。
- 邀请可到期、撤销、一次性兑换；并发和重试也只建立一条双向关系。
- 配对超时后重新核对，双方得到一致关系结果。
- 拖动、单击、双击和远程入口不互相误触。
- 暂停、隐藏、穿透、倒计时气泡和互动文案分别按规则工作。
- 连点不形成无限动画，过期不播、重复不执行。
- 断网、休眠或回执丢失时不虚报本人已看见，不补发陈旧动作。
- 解除后的旧动作无法影响新关系，离线解除明确显示待同步。
- 换电脑重新配对可完成，不依赖不存在的自动找回能力。
- 服务故障不影响本地下班计时、拖动和设置。

## 12. 原需求调整与待确认事项

| 原表述 | 调整 |
| --- | --- |
| 原则不可协商 | 改为可讨论、可验证的设计原则 |
| 情侣专用 | 情侣为重点场景，也允许朋友、家人使用 |
| 长期码，立即绑定，不做安全校验 | 主动生成的一次性短期邀请，不额外弹接受框，保留后台身份与权限验证 |
| 状态必须实时准确，避免猜忌 | 状态描述连接与接收能力，允许检测延迟，不推断注意力或保证消除误解 |
| 本机播放即完成 | 发起动画与客户端接收确认分开，未知结果如实提示 |
| 解绑立即生效 | 区分本机立即停收与服务端确认，补上离线待同步 |
| 本地留记录但不做历史 | 不保存可回看记录，只允许短期去重和回执状态 |
| 首批两套形象 | 保留，明确双方原本就能独立选择，同款也允许 |
| 换电脑待定 | 首期重新配对，多设备与迁移以后设计 |

实现前需要补齐：

- 更精细或正式授权的形象素材；本版已按网络参考完成 Qt 分部件绘制，详见形象来源。
- 捏脸、轻捶的具体画面和时长，是否提前替换其中一个为正向动作。
- 服务部署条件和维护责任。
- 邀请限频、连点合并上限、播放窗口等联调参数。
