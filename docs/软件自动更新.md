# 软件自动更新

从 `v0.5.0-preview.5` 开始支持。更早的程序没有更新器，需要先完整解压此版一次；此后在程序内升级。

## 用户怎么用

- 启动约 8 秒后自动检查版本，之后每 4 小时检查一次；检查失败后 30 分钟重试。有新版时展示版本说明，由用户点击“更新并重启”。检查失败不会打断桌宠。
- 也可通过托盘菜单、动作面板下方“更多”中的“检查更新…”，或设置的“偏好设置 → 软件更新”手动检查。
- 下载、校验和解压在后台完成，下载过程中可点击“取消下载”，程序会清理本次临时文件。准备好后自动退出旧程序，由独立更新器替换程序并启动新版。
- 支持增量更新的客户端点击同一个“更新并重启”按钮后，自动优先下载适用于当前安装版本、且体积更小的增量包；界面显示“下载增量更新”和实际下载大小。没有对应增量包时直接下载完整包。
- 增量包只包含新增及变化文件，未变化文件从本地复制到暂存目录，并逐个核对目标版本的大小及 SHA-256；新版本不再包含的文件不会进入新目录。增量下载失败、校验失败或本地文件缺失/损坏时，会提示并自动切换到完整更新；点击取消不会触发完整下载。
- 新版正常启动并确认后清理旧程序和下载包；下次启动清理已经结束的更新缓存。新版启动失败则恢复并重新启动旧版。
- 配置、已安装角色和搭子身份仍保存在应用数据目录，更新程序不修改它们。用户自行放进程序目录的额外文件保留在旧目录备份中。
- “启动时自动检查更新”可关闭。更新不会在没有点击按钮时静默安装。

请将程序完整解压到独立且有写入权限的文件夹。ZIP 内的 `OffworkPetUpdater.exe`、`release-info.json` 和 `_internal` 都是程序的一部分，需要保留。

## 发布者怎么发新版

服务器无需新增数据库表：保存版本 ZIP 和一份签名 JSON 即可。普通用户不填写更新地址。

- 版本清单：`http://106.54.27.8/offwork-pet/updates/latest.json`
- 版本包：`http://106.54.27.8/offwork-pet/releases/<版本包文件名>.zip`
- 服务器目录：`/var/www/offwork-pet-updates/`
- Nginx 在产品现有 snippet 中增加这两个路径，原有网站及搭子接口保持原配置。

修改 `offwork_pet/__init__.py` 中的版本号后构建并签名：

```powershell
python -m venv work/release-venv
work/release-venv/Scripts/python.exe -m pip install -r requirements-release.txt
work/release-venv/Scripts/python.exe tools/package_release.py --sign-key "$env:USERPROFILE/.codex/credentials/offwork-pet/release-signing.key"
```

签名发版时，默认从 `dist` 保留的最近三个旧版完整 ZIP 分别生成直达新版的增量包（`OffworkPet-v<旧版>-to-v<新版>-delta.zip`）。也可重复指定 `--base-archive <旧版完整ZIP>` 选择基础版本。即使用户跳过中间版本，只要有对应基础版本的包，就能直接增量升级；否则使用完整包。完整 ZIP 继续用于首次安装和回退。请保留旧版完整 ZIP，不要覆盖已发布版本的文件。

签名清单保留原来的完整包地址、大小和哈希，增加签名覆盖的 `deltas` 列表。旧版客户端会继续完整更新，因此用户首次升级到支持增量更新的客户端仍需下载一次完整包；之后更新才会自动选择增量下载。增量不要求用户额外操作，也不改变更新按钮。

私钥通过本机当前用户 DPAPI 加密，客户端只带公钥。私钥不进 Git、不上传服务器，也不放入发布包。请由发布者妥善保留同机同用户的签名凭据；更换签名公钥需要另行设计迁移，不能随意重新生成。

发布必须使用独立的 `release-venv`，避免从 Anaconda 收集数值计算运行库。打包脚本排除 NumPy、SciPy 和 Qt 多媒体模块，并在发现 MKL 时直接失败。角色包只保留已有 PNG/WebP 能力，Windows WAV 音效使用系统 API；另外排除不使用的 PDF、QML 虚拟键盘和 AVIF 解码插件，保留中文、英文 Qt 消息。

上传时使用已保存的服务器凭据，密码仅通过标准输入进入发布脚本，不出现在命令行参数中：

```powershell
$releaseCredential = Import-Clixml -LiteralPath "$env:USERPROFILE/.codex/credentials/offwork-pet/ubuntu-106.54.27.8.clixml"
$releaseCredential.GetNetworkCredential().Password | python tools/publish_release.py --archive dist/OffworkPet-v0.5.0-preview.11-CharacterPacks.zip --manifest dist/latest.json
```

发布脚本先校验签名、完整 ZIP 和清单引用的全部增量 ZIP，所有包上传后逐一核对 SHA-256，最后原子替换版本清单。增量 ZIP 需与完整 ZIP 放在同一目录；任何包缺失或校验失败都不会发布新清单。已发布版本不允许用不同内容覆盖，需增加版本号后再发。签名采用 [cryptography 的 Ed25519 实现](https://cryptography.io/en/45.0.4/hazmat/primitives/asymmetric/ed25519/)。

客户端按内置公钥验证版本清单，并按签名中的大小及 SHA-256 验证下载文件。解压限制文件数、大小及路径，不运行服务器返回的脚本。更新器只替换应用目录，等待旧进程退出后操作；启动确认超时则回滚。

## 验证

```powershell
python -m unittest discover -s tests -v
python tests/integration_updates.py --archive dist/OffworkPet-v0.5.0-preview.11-CharacterPacks.zip --manifest dist/latest.json
```

第二条在临时目录中用实际发布版和独立更新器进行同版本替换演练，验证 Windows 进程退出、目录替换、启动确认、旧文件清理和个人数据保留；不会修改当前真实安装。新旧版本比较、下载、签名和失败回滚另有自动测试。

增量演练在第二条命令上增加 `--from-archive <旧版完整ZIP> --delta-from <旧版本号>`，使用签名清单中对应的增量包组装新版，再运行独立更新器完成替换。`--helper <更新器EXE>` 可在本地演练中指定单独构建的新更新器；正常客户端直接使用暂存目录中校验过的新版更新器。自动测试另覆盖只请求增量 URL、404/损坏后回退完整包、取消不回退、文件新增/删除、签名篡改、暂存文件复核及失败回滚。

每次发布会在 `dist/release-audit-v<版本>.json` 输出体积、组件和 SHA-256 审计，不放进用户压缩包。更新版本说明维护在根目录 `release-notes.txt`。
