# 角色包格式与运行规则草案

更新：2026-10-21。

状态：此文的 v1 核心格式已由 `v0.5.0-preview.1` 实现，仍保留“草案”名称供试用修订。实际使用、能力列表与限制见 [角色包制作与使用](角色包制作与使用.md)；`preview.10` 增加包声明的离散朝向控制，见 [鼠标朝向跟随](鼠标朝向跟随.md)。逐帧区域、在线工坊及可视化编辑仍未实现。

## 目标与第一版范围

同一主程序运行不同创作者制作的角色。包内动作和状态名称不要求相同，安装一个只含静态图的包也应成立。

第一版提供：

- PNG/WebP 静态帧、帧序列与图集播放，逐帧时长，透明背景。
- 一个稳定状态加一个临时动作的播放模型；区域输入、定时、有限条件、状态切换、随机选择。
- 按包声明生成本地菜单和远程无参数互动按钮。
- 安装、切换、更新、删除、兼容性检查与资源预算。

第一版不执行包内 Python、JavaScript、命令行、任意表达式，也不从包内网址自动获取依赖。视频、实时 3D、骨骼动画、多层混合、参数化远程表单与在线工坊以后按能力扩展。

## 一个文件导入，系统管理目录

建议使用 `.petpack` 后缀，内部为 ZIP。普通用户不需要解压。

```text
my-character.petpack
├── manifest.json           # 身份、兼容性、画布、缩略图、来源授权
├── behavior.json           # 动画、动作、状态、区域、规则、菜单、远程入口
├── thumbnail.png
└── assets/
    ├── rest-01.png
    ├── rest-02.png
    ├── touch-01.png
    └── ...
```

不要把用户设置、连接信息、身份凭据和运行缓存装入包。包内容安装后只读；系统生成的索引、缓存及将来的角色存档另存。

建议目录为 `%APPDATA%/OffworkPet/characters/<包标识>/<版本与内容摘要>/`。安装索引记录当前启用版本，应用配置只记录选中的包标识。实际目录名由系统验证和生成，不能把包内未经验证的名字直接拼成路径。

身份字段分开：

| 字段 | 用途 |
| --- | --- |
| 包标识 `id` | 稳定引用，与显示名称无关；建议作者命名空间，如 `example.lulu` |
| 内容版本 `version` | 创作者发布版本；同版本内容不同应报告冲突，不静默覆盖 |
| 格式版本 `formatVersion` | 运行时如何解析包的协议版本 |
| 最低引擎版本 `minEngineVersion` | 所需程序版本，不等于包格式版本 |
| 所需能力 `requires` | 如 `render.frames/v1`、`input.pointer/v1`；必要能力未知则拒绝启用 |
| 内容摘要 | 系统根据校验后的文件内容生成，用于缓存与更新隔离，不由作者随意填写 |

本地包标识用于避免命名冲突，不等于认证过的作者身份。将来的工坊账号和包的归属由工坊管理，不凭 `author` 字段认领别人的作品。

## 最小示例：包自己定义行为

下面两个 JSON 是同一示例包的配置草案；素材文件名为说明用途，没有随文档提供。它包含“静静站着”“开心蹭手”“橘子舞”，这些不是框架保留动作。

`manifest.json`：

```json
{
  "formatVersion": 1,
  "id": "example.lulu",
  "version": "1.0.0",
  "displayName": "示例噜噜",
  "author": "示例作者",
  "minEngineVersion": "1.0.0",
  "requires": ["render.frames/v1", "input.pointer/v1"],
  "thumbnail": "thumbnail.png",
  "canvas": {
    "width": 320,
    "height": 400,
    "anchor": [160, 380]
  },
  "behavior": "behavior.json",
  "credits": [
    {
      "assets": ["thumbnail.png", "assets/"],
      "author": "示例作者",
      "source": "原创示例",
      "license": "由创作者填写实际授权",
      "changes": "由创作者填写修改说明"
    }
  ]
}
```

`minEngineVersion` 比较角色引擎的能力版本，当前为 1.0.0；产品应用版本仍为 0.5.0-preview.1，两者分开。`credits` 的示例文字不是这些素材的真实授权。

`behavior.json`：

```json
{
  "initialState": "standing_on_mat",
  "recoveryState": "standing_on_mat",
  "animations": {
    "quiet_blink": {
      "loop": true,
      "frames": [
        {"file": "assets/rest-01.png", "durationMs": 1200},
        {"file": "assets/rest-02.png", "durationMs": 160}
      ]
    },
    "touch_reaction": {
      "loop": false,
      "frames": [
        {"file": "assets/touch-01.png", "durationMs": 120},
        {"file": "assets/touch-02.png", "durationMs": 180},
        {"file": "assets/touch-03.png", "durationMs": 160}
      ]
    },
    "orange_steps": {
      "loop": false,
      "frames": [
        {"file": "assets/dance-01.png", "durationMs": 150},
        {"file": "assets/dance-02.png", "durationMs": 150},
        {"file": "assets/dance-03.png", "durationMs": 150},
        {"file": "assets/dance-04.png", "durationMs": 150}
      ]
    }
  },
  "regions": {
    "crown": {"shape": "rect", "rect": [100, 40, 120, 90]}
  },
  "states": {
    "standing_on_mat": {"animation": "quiet_blink"}
  },
  "actions": {
    "enjoy_touch": {
      "animation": "touch_reaction",
      "priority": 20,
      "interruptible": true,
      "onBusy": "replace",
      "cooldownMs": 600,
      "after": {"type": "return"}
    },
    "little_dance": {
      "animation": "orange_steps",
      "priority": 10,
      "interruptible": true,
      "onBusy": "enqueue",
      "queueTtlMs": 3000,
      "cooldownMs": 1000,
      "after": {"type": "return"}
    }
  },
  "rules": [
    {
      "id": "touch_crown",
      "event": "pointer.click",
      "region": "crown",
      "when": {"stateIn": ["standing_on_mat"]},
      "then": {"type": "action", "id": "enjoy_touch"}
    }
  ],
  "menu": [
    {"id": "dance_menu", "label": "跳一段橘子舞", "order": 10,
     "invoke": {"type": "action", "id": "little_dance"}}
  ],
  "interactions": [
    {"id": "greet_with_touch", "label": "摸摸头", "order": 10,
     "invoke": {"type": "action", "id": "enjoy_touch"}}
  ]
}
```

示例用“点击头顶”触发一段反应，以展示最小闭环，不等同于连续抚摸。真正随鼠标轨迹反应时，包需要声明通用抚摸能力、使用 `gesture.stroke` 及轨迹参数；框架需先实现该能力。

只有静态画面的最小包：一个单帧动画、一个指向它的初始状态，`actions`、`rules`、`menu`、`interactions` 均可为空。`recoveryState` 可以指向初始状态，也可以省略以选择停止播放并报告错误；即使有恢复状态，其资源也可能损坏，恢复失败后必须停止，不能无限重试。

## 必须在实现时固定的语义

### 动画、状态、动作

- 帧时长必须为正数，播放时间以单调时钟累计。图集帧使用 `file` 加显式 `rect: [x, y, width, height]`，不通过行号猜动作，也不把空白格当有效帧。
- 帧默认覆盖声明的画布；图集单元或裁剪帧另有明确绘制位置，不能每帧按内容包围盒自动拉满，否则角色会忽大忽小。所有尺寸和坐标必须经过范围校验。
- `canvas.anchor` 为该包的稳定定位点。不同动画保持站立基线和比例，由素材制作与预览校验保证；包切换时按各自定位点对齐桌面位置。
- 状态提供基础动画；动作提供临时播放。`after.type = return` 返回启动该动作前的稳定状态，重启基础动画，不重新触发状态进入规则；排队动作在实际开始时捕获返回状态。
- 需要改变状态时使用 `after: {"type": "state", "id": "目标状态"}`。动作串联以后用明确的有限序列扩展，不依赖结束事件无限递归启动下一个动作。
- `recoveryState` 是包的错误恢复声明，不是动作正常结束的默认出口。恢复失败时停止角色，系统菜单和导入入口继续可用。
- 状态计时在临时动作期间暂停，返回时继续；明确切换状态后重新计时。“无操作时长”单独根据有效用户输入记录，播放动画本身不算用户操作。系统暂停期间停止行为计时，恢复后不补播积压事件。

### 事件、条件与规则

- 框架开放版本化事件类型；包可以自由定义区域、状态、动作和定时器标识，不能凭空创造框架没有的输入识别器。
- 第一个实现只开放白名单条件：状态匹配、布尔/数值变量比较、计时与冷却检查，以及它们的有限 `all/any` 组合。变量声明类型、默认值和数值范围，第一版只保存在当前角色运行实例内。
- 规则可选 `rulePriority`，默认为 0。同一事件优先命中更高优先级规则，同级按声明顺序选择第一条；一次事件最多执行一个主行为，不把多条匹配规则全部播放。
- `then` 只允许声明的操作，例如触发动作、切换状态、设置受限变量、在有限候选中随机选择。随机选择的候选与权重在导入时校验，运行时仍受总执行预算限制。
- 本地菜单、远程入口与鼠标规则调用同一个动作调度器，不能各开一个动画播放器。声音、台词同样受系统音量、静音和文本设置控制，包不能修改这些系统设置。
- 静态检查引用与明显无条件循环；运行时还限制单事件处理步数和单位时间切换次数。规则在主线程上的执行必须可终止，不能靠静态校验保证任意组合永不卡住。

### 调度顺序

- 没有临时动作时直接开始。`priority` 仅用于同一包的角色动作，不能用极大数字盖过系统操作。
- `replace`：只有新动作优先级严格更高且当前动作可打断，才替换；否则返回“忙碌”，不自动排队。同优先级不互相抢占。
- `enqueue`：进入有数量上限的队列；待播放时按优先级从高到低，同级先进先出。TTL 从接收时开始计算，开始前重新检查角色实例、能力修订、状态条件和冷却。
- `discard`：当前忙碌时拒绝，不保留待播放任务。
- 冷却从动作实际开始时计算；冷却期间的新请求直接拒绝。同一动作最多保留一个待播请求，不能因重复点击堆积几十次。
- 排队 TTL 到期、角色切换、暂停、删除或断开相关配对时终止不再有效的远程任务，必要时返回取消原因。有限动作播放完成后才释放主播放通道。
- 使用循环动画的临时动作，第一版要求 `maxDurationMs`；无时长限制的长期表现用状态表达，避免一个动作永不结束。
- 菜单和远程入口可选状态条件；发起时和真正开始时都检查。状态已变化则拒绝或取消，不能仅因排进过队列就无条件播放。

## 区域和手势

第一版支持画布坐标中的矩形/椭圆区域，以及按状态或动画替换区域定义。区域名称没有保留的 `head/body/face`；作者可以定义自己需要的位置。

多个区域重叠时按区域优先级，再按声明顺序选一个目标。固定坐标只适合该画布和相近姿态；明显位移、转身或缩放后的素材需要相应区域，不能靠静态框宣称精准命中。

建议系统手势约定：

| 用户输入 | 系统解释 |
| --- | --- |
| 左键短按释放，未达到移动阈值 | 点击候选，结合双击窗口后派发单击/双击 |
| 普通左键移动超过阈值 | 移动窗口，取消点击/长按/抚摸候选 |
| 保持在阈值内达到长按时间 | 派发长按；释放不再补发单击 |
| 按住系统设定修饰键并移动 | 在角色区域内识别抚摸轨迹，不移动窗口 |
| 右键或托盘菜单 | 打开系统菜单与包动作分组 |

这是建议的第一版绑定，具体修饰键需要交互试用后确定，并检查现有缩放/透明度快捷键。双击打开设置可以保留为系统默认绑定；以后开放设置重映射，但包不能自行覆盖用户选定的系统绑定。

抚摸识别使用区域内轨迹、持续时间、移动距离和方向变化，而不是把每次鼠标移动都当一次摸头。每次会话有开始、更新、结束、取消，限制更新频率，鼠标释放、失焦、切换角色时必须清理。

## 远程能力与版本

包公开的 `interactions` 只是入口，本地 `invoke` 不发送给搭子或服务端。框架从当前角色包生成公开能力快照：包标识、包版本、内容摘要、本次加载修订、互动 ID 与展示名称。

消息应区分：

- `interactionId`：接收方包公开的互动 ID，例如 `greet_with_touch`。
- `actionId`：本次消息的唯一编号，用于去重、取消与回执，不是本地动画动作 ID。
- `capabilityRevision`：发送方看到的能力修订；接收方不一致就拒绝并刷新能力。
- `relationId`、有效期等：保留既有配对和消息约束。

服务端保存当前会话的受限能力描述并检查请求是否在内；接收方还要检查实际加载实例及调度条件。切换后清除旧快照，成功启用新包后再公布新快照。断线重连重新同步，不从数据库中的旧快照推断当前在线能力。

第一个版本不接收任意参数，不默认合并连续消息为 `count` 次。以后需要计数、强度或选项时，再由能力明确声明类型、范围和合并方式。

现已保留 `/v1/*` 供旧版客户端使用，并增加 `/v2/devices`、`/v2/connect`。新客户端只发送 v2 动态能力，不让旧服务端误收新包动作；版本不兼容时提示升级。

## 导入与制作工具的责任

导入按“暂存 → 校验 → 登记 → 用户选择后激活”执行；是否立即启用可以由导入界面提供选项。重复导入相同内容不重复占用磁盘；更新失败不破坏旧版。

校验至少覆盖：

- 必需字段、格式版本、必要能力、唯一标识和所有跨文件引用。
- 路径必须在包内；拒绝绝对路径、路径穿越、符号链接与规范化后冲突的重复文件。
- 文件数量、解压大小、压缩膨胀、图像尺寸、解码内存、帧时长、队列及规则复杂度的上限。
- 动画存在、有效帧非空、区域范围、初始状态有效、临时动作可结束、菜单与远程入口确实有目标。

制作工具复用运行时的解析器和预览播放器，避免“制作工具能播，正式程序不能播”。工具需要让创作者：

1. 导入素材，查看帧顺序、时长、透明边缘、循环和不同动作间的比例/定位。
2. 画交互区域，绑定点击、抚摸、菜单等入口。
3. 选择初始状态、结束去向、打断与冷却，模拟连续输入和远程互动。
4. 看到具体错误位置，例如 `actions.little_dance.animation` 引用了不存在的动画，而不是只提示“包无效”。
5. 填写作者、来源和授权后导出一个 `.petpack`。

制作工具可以调用 AI 生成动作，但生成结果仍要经过预览与校验。角色大小突变、额外肢体和不自然循环不能靠配置正确就自动通过视觉验收。

## 工坊如何接入

工坊提供封面、演示、作者、版本、兼容性、授权、下载和更新信息。客户端取得包文件后，仍走同一个导入器；网站不下发本机执行代码。

内容版本更新由用户选择，不能在角色播放中静默改写素材。更新后的能力变化重新同步给搭子。未来若有自动更新，也应复用版本安装和回退机制。

第一阶段允许用户直接发送包文件给朋友。等包规范和本地使用稳定后，再做工坊上传、搜索、内容审核、下载统计等线上功能；这些不阻塞角色系统本身。
