# 自托管联网服务

桌宠的本地角色、动画和桌面互动可独立运行。联网时由使用者在“搭子 → 服务器”中填写地址；新客户端没有默认业务服务器，也不会在连接失败后转回原服务器。不同实例的设备凭证、关系和集会独立。

## 部署

准备已安装 Docker Engine 和 Compose v2 的机器，取得完整项目源码。以下命令从仓库根目录执行，初始化脚本只需要 Python 标准库：

```sh
python tools/init_selfhost.py
docker compose up -d --build
docker compose ps
```

初始化只生成本地 `.env`，不会覆盖已有文件。管理员用户名和随机密码在该文件中，勿公开或提交。数据库密码同样随机生成。默认绑定 `127.0.0.1:8765`；本机打开 `http://127.0.0.1:8765/admin/hosting`，登录后配置实例和生成接入码。另有原设备/集会管理页面 `/admin/`。

默认 Compose 服务为一个后端实例和 PostgreSQL 16，数据库不映射宿主机端口。构建不要求部署者安装 Node 或 Qt。已构建的原管理页面若不在源码归档中，可使用独立自托管管理页 `/admin/hosting`。

`.env` 中 `SERVER_NAME`、`CHAT_DAYS` 是首次初始化的种子值，之后以后台保存的数据库配置为准；`ADMIN_USER`、`ADMIN_PASSWORD` 是运行凭据，改动后需重建应用容器。实例 ID 和会话签名密钥保存在数据库中。更改管理员凭据会使旧登录会话失效。

### 公网 HTTPS

将域名解析至服务器，在 `.env` 追加 `DOMAIN=pet.example.com`，开放 80/443 后执行：

```sh
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

此方式使用 Caddy，移除应用宿主机端口映射，统一经网关提供 HTTPS/WSS。覆盖文件的 `!override` 要求 Compose 2.24.4 或更新版本。后台地址为 `https://你的域名/admin/hosting`，客户端填写 `https://你的域名`。证书签发依赖真实 DNS、网络及证书机构条件。

已有反向代理可只部署基础 Compose，将 `/` 的 HTTP 和 WebSocket 一并转发至 `127.0.0.1:8765`。按实际代理来源配置 `OFFWORK_TRUSTED_PROXIES`，勿对直接暴露的服务盲目信任任意转发头。本地测试可用 HTTP，远程 HTTP 会在客户端提示确认；HTTPS 证书错误不能跳过。

## 接入与数据

- Compose 新实例默认要求服务器接入码；后台可切换自由加入或关闭新设备加入。接入码有过期时间和可用次数，原文仅创建时显示，数据库只保存摘要。
- 服务器接入码与搭子配对邀请码不同。每台设备注册后获得自己的凭证；管理员禁用设备时关闭其连接并阻止重新认证，启用后可恢复原身份。
- 接入码只在客户端内存中暂存；设备凭证沿用 Windows 当前用户 DPAPI，按服务器根地址分开保存。服务器地址变化不会自动迁移配对关系；同一实例变更域名的身份迁移仍需后续工具支持。
- 设备、关系、集会、接入码、实例设置、聊天历史及新管理操作审计保存在 PostgreSQL。新管理页的操作记录不等于已覆盖全部旧后台操作。
- Compose 默认保存聊天 30 天。后台可修改保留天数；0 表示不再保存并清空已有服务端聊天。历史接口 `GET /v2/chat/history` 使用设备 Bearer 凭证，只允许当前集会成员读取该集会最近 100 条记录。第一版客户端仍使用实时聊天界面，历史查询 UI 尚未接入。
- 原有本机聊天日志继续存在。服务器保存策略见 `GET /api/server/info`，客户端不把“自托管”解释为端到端加密；服务器运营者能访问服务端保存的数据。
- 后端单进程，禁止直接加多个 worker。当前不支持跨服务器聊天或集会联邦。

## 角色资源

在线角色浏览和下载使用客户端所选服务器。新实例目录为空，不会自动访问原服务器。通过管理员命令发布已获授权的角色包：

```sh
docker compose cp /你的路径/character.petpack app:/data/import.petpack
docker compose exec app python -m server.manage import-pack /data/import.petpack
```

发布执行正式包校验，目录接口、缩略图和原包下载由同一实例提供，发布文件位于资源卷。第一版同一角色标识不能重复发布，尚未提供角色版本更新/下架或台词库管理，不执行包脚本。资源目录和下载当前为公开只读，不能用它存储私密素材。

程序更新仍沿用发布者签名和独立更新渠道；更换业务服务器不授予对方替换程序的权限。分支维护者应在自己的构建中明确配置更新源与公钥。

## 升级与备份恢复

数据库使用 `schema_migrations` 记录版本；旧 SQLite 启动时采用事务迁移，保留原记录。程序遇到高于自身支持的数据库版本会拒绝启动。迁移后不能保证直接启动旧版本镜像，回退应恢复升级前整套备份。

更新前从仓库根目录执行：

```sh
python tools/selfhost_backup.py backup backups/升级前备份 --project offwork-pet
docker compose up -d --build
```

对原本运行的应用，备份会短暂停止它，使数据库和资源形成一致备份，完成或失败后尝试恢复运行。备份期间勿执行资源发布命令。备份包含 `.env`，应私密保存到其他机器；卷持久化本身不是备份。不要执行 `docker compose down -v` 删除生产卷。

当前备份格式为 v2，包含每个文件的长度和 SHA-256 清单。恢复前先校验全部文件及资源归档路径，拒绝链接、特殊文件及目录穿越。旧开发阶段的 v1 备份需重新生成，不能直接交给当前恢复命令。备份会保留应用原来的运行/停止状态，原本停止的应用不会被启动。

校验清单用于发现文件损坏，不是发布者签名或来源认证；仍应只恢复自己的可信备份。

使用 HTTPS 覆盖配置部署时，备份和恢复也应带上相同的 Compose 文件，例如追加 `--file compose.yaml --file compose.https.yaml`，避免采用不同的端口和代理配置。

恢复到另一台机器时放好对应版本源码，恢复并按需要调整 `instance.env` 为根目录 `.env`，先构建应用镜像并仅启动空数据库，再执行：

```sh
docker compose build app
docker compose up -d db
# 等待 db 健康后，目录必须是本工具产生的可信完整备份。
python tools/selfhost_backup.py restore backups/升级前备份 --project offwork-pet
```

恢复工具拒绝覆盖已有应用表或非空资源目录。实例 ID、身份摘要、配对和聊天随数据库恢复；客户端地址不变时可以复用原凭证。

恢复还要求目标应用处于停止状态。文件校验失败时不执行数据库和资源写入；数据库或磁盘恢复阶段发生故障时应保留日志，并重新准备空目标后再恢复，不能将跨数据库/文件卷的恢复视为一个原子事务。

## 从现有 SQLite 迁入 PostgreSQL

先备份并停掉旧服务，复制 SQLite 文件和 WAL 的一致快照。目标实例业务数据必须为空：

```sh
docker compose cp /你的路径/offwork.sqlite3 app:/data/legacy.sqlite3
docker compose exec app python -m server.manage import-sqlite /data/legacy.sqlite3
```

工具只读打开源库并在临时副本上升级，事务导入设备、关系、集会等记录，保留设备 token 摘要。目标实例设置由新部署管理。旧官网目录是另一套数据，当前导入工具不迁移官网目录；角色包通过发布命令重新导入。迁移命令执行时须避免其他设备注册或管理操作。

当前导入每批处理 500 行，先核对字段再导入；整次业务数据迁移处于一个事务内，出现不兼容字段或写入错误时回滚。数据库版本 3 增加聊天过期、接入码过期和审计排序索引，兼容已有版本 2 数据。

实例设置在单个服务进程内缓存，后台修改提交成功后更新缓存。过期清理每分钟运行一次，历史查询同时按当前保存期限过滤，不会在等待清理期间返回过期消息。请通过后台修改设置；直接修改数据库的设置项后需重启应用进程。

注册、登录及管理控制请求限制为 16 KiB，超出返回 413；角色包传输仍使用独立的 64 MiB 压缩包限额。已保存的准入/保留设置以数据库为准，相关初始化环境变量只用于首次填充。迁移历史不连续时服务拒绝继续升级，需恢复一致的数据库备份。
