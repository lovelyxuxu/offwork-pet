# 双人互动：运行与部署

## 1. 这版包含什么

- 双方独立加载角色包，可以使用同款或动作完全不同的角色。
- 默认关闭联网；首次主动开启后申请匿名设备身份，凭证用 Windows 当前用户 DPAPI 保护。
- 一次性 8 位邀请、10 分钟有效、撤销、一对一绑定、单方面解除。
- HTTP/HTTPS 与对应的 WS/WSS 连接、状态同步、暂停、隐藏时拒收，v2 按对方当前角色的能力生成互动按钮。v1 固定动作仅为旧客户端保留，v2 不默认合并连续请求。
- 动作 5 秒有效、标识去重、接收确认、断线重连、离线解除待同步。
- 不做注册、聊天、离线补发、已读或互动历史。

产品客户端统一连接内置服务 `http://106.54.27.8`，不向用户展示服务地址输入和 HTTP/HTTPS 技术说明。双方开启联网并使用邀请码即可配对，无需自行部署或输入联网信息。

服务地址由 `offwork_pet/buddy.py` 中的 `SERVICE_ENDPOINT` 维护，不属于用户配置；旧配置文件中的 `relay_url` 被忽略，之后保存时不再写入。测试可通过构造参数注入独立服务地址，不改变产品默认地址。

## 2. 本机启动服务

在仓库根目录执行：

```powershell
python -m pip install -r server/requirements.txt
python -m server --host 127.0.0.1 --port 8765
```

默认数据库为当前目录的 `data/offwork.sqlite3`。可在启动前通过环境变量 `OFFWORK_DB` 指定持久化位置，数据库及凭证均被 Git 忽略。

健康检查：`http://127.0.0.1:8765/health`。

## 3. 一台电脑验证两个独立客户端

```powershell
python main.py --profile alice
python main.py --profile bob
```

分别在两个宠物的右键“搭子…”面板开启联网。一方生成邀请，另一方输入即可配对。两个配置目录和设备身份相互隔离；不需要创建两个账号。这种手动启动方式仍连接产品服务。

需要与产品服务隔离的本机联调时，运行 `python tests/integration_network.py`。脚本自动启动临时服务，并通过 `Pet(..., relay_endpoint=endpoint)` / `BuddyClient(..., endpoint=endpoint)` 注入本机地址，使用临时数据库与身份目录。

profile 存在 `%APPDATA%/OffworkPet/profiles/<名字>`，不应在两个测试 profile 中设置开机启动。默认启动仍使用原有主配置。

测试：双方选同款/不同款，捏脸或轻捶，暂停/恢复，隐藏/显示，关闭联网/重连，离线解除后再联网。

## 4. 产品服务与部署维护

普通用户无需进行本节操作。本节仅供产品维护者部署、排查和将来调整服务地址使用。2026-10-22 已按用户授权升级线上搭子服务；`http://106.54.27.8/health` 返回 `{"ok":true,"protocol":2,"supported_protocols":[1,2]}`。现有设备身份、搭子关系和邀请码数据库保持原路径，v1 继续兼容旧客户端，v2 支持角色包动态互动。

本次部署及回滚记录见 [线上搭子服务升级记录](线上搭子服务升级记录.md)。如客户端此前因旧服务停止连接，在“搭子”面板重新开启联网即可。

服务端只运行一个进程/一个 worker，当前在线会话、动作与回执在该进程的内存中。不要直接增加多个 worker，否则不同进程之间看不到对方的连接。

### 没有域名：HTTP + 服务器 IP

在服务器的项目根目录执行：

```shell
python -m pip install -r server/requirements.txt
python -m server --host 0.0.0.0 --port 8765
```

如果选择直接暴露服务端口，需在防火墙和云安全组中放行该端口，并由维护者更新代码中的服务根地址；也可以使用反向代理。当前产品根地址是 `http://106.54.27.8`，不是本段的 8765 端口示例。根地址不包含 `/v1` 路径，可通过 `<根地址>/health` 检查服务是否可达。

HTTP 自动搭配普通 WebSocket。`0.0.0.0` 只用于服务监听，不能作为客户端连接目标。服务部署方式由维护者处理，用户界面不提供服务器选择。

HTTP 不加密设备凭证与互动数据。桌面端本机凭证存储仍由 Windows DPAPI 保护，但这不等于网络传输已加密。

### 可选：HTTPS/WSS

后续需要加密时，可以让服务监听 `127.0.0.1:8765`，前置 Caddy 等反向代理处理 HTTPS/WSS，由维护者更新应用内置的服务根地址。示例 Caddyfile：

```caddyfile
pet.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

该示例域名需替换并指向实际服务机器，证书与网络条件由部署环境提供。HTTPS 是可选部署方式，客户端不再强制远程服务使用 HTTPS。示例不代表已开通云服务或完成公网部署。

服务端只保存设备验证信息、当前关系和邀请，不保存动作内容。备份数据库会影响设备与关系的恢复；不要在已有客户端配对后随意换空数据库。服务重启会丢弃未完成动作，客户端重新核对关系，不补发。

`v0.5.0-preview.1` 增加 `/v2/devices` 和 `/v2/connect`，原 `/v1/*` 继续供旧客户端使用。v2 的当前角色与互动清单保存在在线会话中；设备表原有 `character` 文本列可保存包标识，无需新增表或手工插入角色数据。升级必须保留原 `OFFWORK_DB`。新旧协议之间不翻译动作，会明确提示双方升级。

若反向代理仅配置了 `/v1/*`，上线时还需把 `/v2/*` 转发到同一个搭子服务，并为 `/v2/connect` 保留 WebSocket Upgrade 支持；只更新 Python 服务但漏掉代理路由，新客户端仍无法连接。

## 5. 操作与状态

- 本地单击仍然摸自己的宠物，远程动作通过“搭子…”面板发送。
- v2 连点不合并，由角色动作的冷却、忙碌策略与系统限频处理；“已接收/已排队”仅表示对方程序接受，不表示本人看见或动作已播放完成。
- 接收端最多每 8 秒启动 3 组远程动画，超出暂时拒绝，防止连点长期占据宠物。
- 超时或断线可能显示“未确认送达”，不自动重发，避免同一动作重复播放。
- 暂停或隐藏会停止接收且清空待播动作；穿透只影响鼠标，不影响接收。
- 断网时对方状态可能短暂滞后，心跳有效期约 30 秒；自己失联时对方状态显示未知。
- 解除连接不需要对方批准。自己离线时先停收并保存待同步解除，重连先解除再恢复其他操作。
- 换电脑/重装会产生新身份，首期由另一方解除旧关系后重新配对。

## 6. 自动验证

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python tests/integration_network.py
python tests/integration_relay_transport.py
```

第二条测试脚本会启动临时本机服务和两个 Qt 客户端，使用临时数据库与身份目录，验证真实 v2 HTTP 注册、WebSocket、DPAPI、配对、角色能力发现、动态互动、接收回执、暂停、隐藏、重连和离线解除。它会生成 `outputs/` 预览，结束时关闭测试客户端和临时服务。

`integration_relay_transport.py` 默认只启动临时本机服务，覆盖实际服务启动入口、v1/v2 双协议、16–32 KiB 角色能力清单、身份复用和互动回执。公网部署验证由维护脚本显式调用，并只清理该次注册的测试身份。
